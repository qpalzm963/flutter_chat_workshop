# 教師教學手冊：Flutter 即時聊天室工作坊（控制台與課堂引導指南）

> 這份手冊是給**講師**上課時對照使用的操作指南：把「課程進度」、「學員實作步驟」與「講師控制台（`http://localhost:8080/admin`）要按的按鈕」串在一起，避免看到控制台不知從何下手。

---

## 零、課前啟動與控制台快速導覽

### 1. 啟動 Server

```bash
cd server
dart run server.dart --admin=Vince --data=state.json
```

- `--admin=<名字>`：填入講師自己的暱稱。用同名登入 App 後，可在聊天室直接對特定學員下指令（例如 `/drop Amy`、`/zombie @all`）。
- `--data=state.json`：**跨週上課必帶**。會持久化儲存訊息、房間、分房、已讀水位線、行為等級與全域延遲（注意：已存檔時，存檔內的行為等級與延遲會覆蓋啟動參數）。
- 課前自檢（不需先開 Server）：`cd server && dart run smoke_test.dart`，看到 `ALL PASSED ✅` 即可。

### 2. 控制台介面四個重點區域

瀏覽器開啟 `http://localhost:8080/admin`：

| 區域 | 位置 | 主要用途 |
| :--- | :--- | :--- |
| **頂部列 + 連線條** | 最上方 | 切換 **行為等級**（`純字串` / `回音 (L1–3)` / `ACK (L4+)`）、設定 **全域延遲**（`設為 2 秒` / `歸零`）、點 **投影給同學** 放大顯示 IP 與啟動指令、開 **WS 測試視窗** |
| **逐堂小抄** | 連線條下方 | 點選 `L1`～`L9` 頁籤並展開，裡面已經幫你做好每堂課的「一鍵預設按鈕」 |
| **左欄：學員連線與故障演練** | 左側 | 看誰在線 / 假死 / 被拒連；單獨或全部觸發 `踢斷 5 秒 (/drop)`、`假死 (/zombie)`、`拒絕連線`；下方有 **重連時間軸** |
| **中欄與右欄：分房與房間監看** | 中間 / 右側 | 中欄切換「各自私人房 / 兩兩一組 / 全班大廳」、建立自訂群組、點選房間；點選房間後可在右欄以講師身分發言、**灌測試訊息**、強制調整 **已讀水位線** |

> [!WARNING]
> 控制台 `/admin` **沒有密碼驗證**，請勿將 `/admin` 網址投影給學員；要投影連線資訊時，請按右上角的 **「投影給同學」** 按鈕。

### 3. 開課前 5 分鐘檢查清單

1. **網路與防火牆**：講師與學員實機需在同一個 Wi-Fi 區網；macOS 若跳出 `dart` 連入連線權限詢問請按「允許」。
2. **確認行為等級與延遲**：檢查頂部列，確認 **全域延遲 = 0 ms**（避免上次課程殘留），並依該堂課切換好行為等級。
3. **投影連線資訊**：按「投影給同學」，讓學員依畫面指令啟動 App（第二台模擬器務必命名為 `名字-2`，例如 `Amy` 與 `Amy-2`）。
4. **講師自己開一台 App**：用 `--admin` 指定的名字登入，方便現場示範與在聊天室下指令。

> [!IMPORTANT]
> **學員取名規則（第 1 堂務必先講）**：Server 會用名字裡 `-` 前面的字判斷是不是同一個人。`Amy` 和 `Amy-2` 會自動分進同一間私人房；`Amy` 和 `Bob` 則會分到不同間私人房。

## 第 1 堂：接通 + 收發（純字串 → JSON）

- **Git 分支**：學員起點 `step-1-connect` ／ 參考解答 `step-1-connect-done`
- **目標**：建立第一條 WebSocket 連線，先互傳純字串，再升級成 JSON 格式區分發送者與事件。

### 課前控制台設定
1. 點開「逐堂小抄」→ `L1 接通收發` → 點 **「① 課前：純字串 + 私人房」**（或手動將頂部行為等級切到 **`純字串`**、中欄分房按 **`各自私人房`**）。
2. 確認全域延遲為 `0 ms`。
3. 按右上角 **「投影給同學」**，讓學員開啟 `step-1-connect` 分支並執行 `flutter run --dart-define=USER=名字 --dart-define=HOST=<IP>`。

### 課中步驟引導
1. **0–20 分（開場與觀念）**：
   - 提問：「要做即時聊天，以前會怎麼做？」帶出短輪詢、長輪詢、SSE 與 WebSocket 的差異。
   - 講師用終端機 `curl` 示範 WebSocket 握手，讓學員看到 `101 Switching Protocols`；也可打開控制台 **「WS 測試視窗」** 現場連上去傳純文字示範。
2. **20–35 分（實作階段 A：純字串收發）**：
   - 請學員開啟兩台模擬器（例如 `Amy` 與 `Amy-2`），在中欄確認兩台都進入同一個 `private:Amy` 房間。
   - 學員實作連線 `WebSocketChannel.connect`、用 `sink.add` 送出純字串、監聽 `stream` 並更新畫面。
   - **驗收**：`Amy` 傳訊息，`Amy` 和 `Amy-2` 都會收到純文字。
3. **35–50 分（實作階段 B：升級為 JSON）**：
   - 拋出問題：「現在畫面分不出是誰講的，以後要加心跳或已讀也分不出事件種類。」
   - **⚠️ 控制台關鍵操作**：在學員準備測試 JSON 解析前，於控制台點 **`回音 (L1–3)`**（或小抄裡的 **「② 切到回音」**）。
   - 學員改送 `{"type":"send","text":...}`，並解析收到的 `{"type":"message","sender":...,"text":...}`，最後加上 `dispose()` 關閉連線。
4. **50–60 分（大廳時刻 + 結尾鉤子）**：
   - **控制台操作**：點中欄的 **`全班大廳`**（或小抄 **「③ 切全班大廳」**），讓全班在 `lobby` 互傳訊息慶祝。
   - **結尾鉤子**：在左欄選一位學員按 **`假死 (/zombie)`**，請講師或鄰座在大廳發話，讓大家親眼看到「那位學員畫面顯示已連線，卻收不到任何訊息」，引出第 2 堂心跳機制。

### 常見卡關排解
- **學員開兩台模擬器卻互傳看不到**：檢查左欄「分配房間」，是否因為取成兩個不同名字（如 `Amy` 與 `Bob`）而被分進不同私人房，請改名為 `Amy` 與 `Amy-2`。
- **學員解析 JSON 時 `FormatException`**：代表控制台等級還停留在 `純字串`，請切到 **`回音 (L1–3)`**。

### 第二階段修改位置與卡關引導（starter 未列 TODO）
- **升級 JSON 與收尾要改哪裡**：都在 `app/lib/data/chat_controller.dart`
  - `send(text)`：改用 `jsonEncode({'type': 'send', 'sender': me, 'text': text})` 送出。
  - `connect()` 的 `listen`：改用 `jsonDecode` 解析，先檢查 `json['type'] == 'message'` 再建立 `Message(sender: json['sender'], text: json['text'], ts: json['ts'])`。
  - `dispose()`：取消 `_sub?.cancel()`、關閉 `_channel?.sink.close()`、關閉 `_out.close()`。
- **卡住引導**：若學員問為什麼要檢查 `type == 'message'`，可預告第 2 堂會有 `pong`、第 4 堂會有 `ack`，先養成過濾事件習慣才不會把系統封包當成聊天訊息印出來。

### 講師補充參考重點（結尾 10 分鐘）
- **WS 怎麼帶登入身分**：WebSocket 連線建立後無法再改 HTTP Header，實務上常在握手時透過 Query String 帶一次性短期 Token（或於連線後第一包送出驗證訊息），不要直接把長效密碼放 URL。
- **為什麼正式環境要用 `wss://`**：加密防止中間人竊聽與竄改，且許多公司/公共網路的 Proxy 會擋掉明文 `ws://` 升級請求。

## 第 2 堂：心跳 + 自動重連（Backoff + Jitter）

- **Git 分支**：學員起點 `step-2-heartbeat` ／ 參考解答 `step-2-heartbeat-done`
- **目標**：偵測假死連線（Heartbeat Ping/Pong），並在斷線時用 Exponential Backoff + Jitter 自動重連。

### 課前控制台設定
1. 點「逐堂小抄」→ `L2 心跳重連` → **「課前：切到回音」**（行為等級 **`回音 (L1–3)`**、延遲 `0 ms`）。
2. 分房維持 **`全班大廳`**（或依課堂人數調整）。

### 課中步驟引導
1. **0–20 分（回顧與觀念）**：
   - 回顧第 1 堂結尾 `/zombie` 現象，說明 NAT 逾時、切背景導致 TCP 假死的原因。
   - 講解應用層 `ping`/`pong`（課堂 10 秒 ping、5 秒 pong 逾時；正式環境 25–30 秒）與 Exponential Backoff + Jitter 避免 Thundering Herd。
2. **20–50 分（實作）**：
   - 引導學員在 `ChatSocket` 實作：定時送 `{"type":"ping"}`、5 秒沒收到 `{"type":"pong"}` 主動斷線；在 `onDone`/`onError` 排程重連（`min(30, 2^n)` 秒 + 隨機 0–999ms Jitter）；連上時重置重試次數；透過狀態串流驅動上方連線橫幅，並在 `dispose` 清理 Timer。
3. **50–60 分（驗收 + 結尾鉤子）**：
   - **驗收 1（測心跳）**：請學員自己在聊天室輸入 `/zombie`（或講師在左欄對個別學員按 **`假死`**），觀察是否會在約 15 秒內主動斷線並重連成功。
   - **驗收 2（看重連時間軸）**：在左欄點 **`全部踢斷 5 秒`**（`/drop @all`），把視線帶到左欄下方的 **「重連時間軸」**，可以看到大家分散在 5 秒後的不同時間點連回（綠點＝連上、紅點＝503 被拒）。
   - **結尾鉤子**：趁某位學員被踢斷的 5 秒內，講師在右欄選取 `lobby` 送出幾句話；學員連回來後發現「剛剛斷線期間大家講的話不見了！」，埋下第 7 堂補洞的伏筆；接著連發多句訊息帶出鍵盤遮擋問題，引出第 3 堂。

### 講師補充參考重點（結尾 10 分鐘）
- **切背景 / 被殺掉後怎麼收訊息**：行動端 OS 會凍結背景 WebSocket，必須靠系統推播（FCM / APNs）喚醒通知；使用者點擊通知進 App 後，透過延遲導航佇列等首頁與房間資料就緒再跳進指定聊天室。

### 第二階段修改位置與卡關引導（starter 未列 TODO）
- **加上 Jitter 與 `dispose` 清 Timer 要改哪裡**：都在 `app/lib/data/chat_socket.dart`
  - 重連排程方法：在 `min(30, pow(2, retry))` 秒之後加上 `Random().nextInt(1000)` 毫秒，避免全班同一秒同時重連。
  - `dispose()`：加入 `_disposed = true;` 並取消心跳、pong 逾時、重連三個 `Timer`（且在排程重連前檢查 `if (_disposed) return;`）。
- **卡住引導**：若學員反應「按 `/drop` 大家還是一起撞進來」，檢查是否忘了加隨機毫秒，或 `retry` 在連上後沒有歸零。

## 第 3 堂：反轉列表 UI（Bottom-anchored）

- **Git 分支**：學員起點 `step-3-reverse-list` ／ 參考解答 `step-3-reverse-list-done`
- **目標**：把聊天列表改成底部錨定（`reverse: true`），並實作「往上翻看舊訊息時不強制拉回，改顯示『有新訊息 ↓』提示」。

### 課前控制台設定
1. 確認行為等級為 **`回音 (L1–3)`**、全域延遲 `0 ms`。
2. 建議分房為 **`兩兩一組`** 或 **`各自私人房`**（兩台模擬器方便自己互測）。

### 課中步驟引導
1. **0–20 分（痛點與觀念）**：
   - 演示一般正向 `ListView` 進房跳到底部閃爍、鍵盤彈起蓋住最新訊息的痛點。
   - 解釋 `reverse: true`（index 0 在最底、offset 0 就是底部）與 `ListView.builder` 虛擬化效能。
2. **20–50 分（實作）**：
   - 學員在 `ChatPage` 實作：`ListView.builder(reverse: true)` 搭配最新在前的列表；用 `ScrollController` 判斷是否停在底部（`offset <= 某閾值`）；當人不在底部且有新訊息進來時顯示「有新訊息 ↓」按鈕，點擊或自己送出訊息時捲回底部。
3. **50–60 分（驗收 + 結尾鉤子）**：
   - **驗收**：進房直接停在底部不閃爍；點輸入框彈出鍵盤會自然把訊息往上推；往上滑看舊訊息時，請鄰座傳訊，畫面應出現提示鈕。
   - **效能壓力測試**：在中欄點選學員所在的房間，於右欄點 **`+1000`**（或小抄 **「選取房灌 +1000 則」**），讓學員快速滑動確認列表依然順暢。
   - **結尾鉤子**：在頂部列「全域延遲」按 **`設為 2 秒`**（`2000 ms`），請學員送出一句話，感受「按送出後要等 2 秒畫面才出現自己剛講的話」的卡頓感，引出第 4 堂樂觀更新。

### 講師補充參考重點（結尾 10 分鐘）
- **插入新訊息造成畫面位移**：`reverse: true` 時新訊息插在 index 0 仍會讓上方閱讀位置微幅移動，進階解法是使用 `CustomScrollView` 搭配 `center` key 錨定目前閱讀的元件。
- **圖片降採樣**：聊天室有大量圖片時，傳入 `Image.network(..., cacheWidth: ...)` 以顯示寬度解碼，避免原圖解碼吃光記憶體。

### 第二階段修改位置與卡關引導（starter 未列 TODO）
- **「不拉回 + 有新訊息提示」要改哪裡**：都在 `app/lib/ui/chat_page.dart`
  - `_isAtBottom`：用 `_scroll.offset < 60`（`reverse: true` 時 `0` 是最底部）判斷是否在底部。
  - `_onScroll()`：滑回底部時把 `_hasUnseen` 設回 `false`。
  - 收到新訊息時：若不在底部且不是自己剛送的，顯示「有新訊息 ↓」浮動按鈕；點擊按鈕或自己送出時 `_scroll.jumpTo(0)`。
- **卡住引導**：提醒學員 `reverse: true` 之後，「底部」是 `offset == 0` 而不是 `maxScrollExtent`，很多同學會把判斷寫反。

## 第 4 堂：樂觀更新 + ACK + 冪等

- **Git 分支**：學員起點 `step-4-optimistic-ack` ／ 參考解答 `step-4-optimistic-ack-done`
- **目標**：實作 Optimistic UI（秒上屏）、訊息狀態機（`sending` → `sent` / `failed`）、5 秒 ACK 逾時，以及用 `client_msg_id` 做冪等去重。

### 課前控制台設定
1. **⚠️ 關鍵切換**：開場時把頂部行為等級切到 **`ACK (L4+)`**（小抄 **「① 開場：切 ACK + 維持 2s 延遲」**）。
2. 先故意保留 **全域延遲 `2000 ms`**，用來示範「就算網路慢 2 秒，樂觀更新還是秒上屏」。

### 課中步驟引導
1. **0–20 分（回顧與觀念）**：
   - 說明 `ACK (L4+)` 模式下，Server 收到訊息後不再把 `message` 回送給發送者自己，而是只回傳 `ack`（內含 `client_msg_id` 與 Server 核發的 `seq`）。
   - 用「掛號信與回條」講解狀態機與冪等性。
2. **20–35 分（實作 Stage 1 — 先故意做錯重試）**：
   - 學員在 `Message` 加入 `clientMsgId`、`status`、`seq`。
   - 送出時先以 `sending` 插入列表再送出 JSON；收到 `ack` 改為 `sent` 並填入 `seq`；超過 5 秒沒收到 `ack` 標記為 `failed`（顯示紅點）。
   - **故意埋錯**：點擊紅點重試時，讓程式「重新產生一個新的 UUID」。
   - **示範完秒上屏後**：在控制台按頂部列延遲 **`歸零`**（`0 ms`），避免接下來測 `/delay`（3 秒）疊加 2 秒延遲導致直接超過 5 秒逾時！
3. **35–45 分（翻車現場演練）**：
   - 請學員在聊天室輸入 **`/fail`**（Server 會照存照廣播給對方，但故意不回傳 ACK）。
   - 5 秒後發送者看到紅點，點擊紅點重試 → **翻車**：對方畫面出現兩則一模一樣的訊息！引導學員找出原因。
4. **45–60 分（修正、驗收與結尾鉤子）**：
   - 學員修正重試邏輯，改為**沿用原本的 `clientMsgId`**。
   - **驗收**：輸入 `/delay`（秒上屏，3 秒後轉勾勾）；輸入 `/fail`（5 秒後變紅點，連點重試，對方只會看到一則，不會重複）。
   - **結尾鉤子**：請學員直接 **殺掉 App 重開**，剛才聊的內容全部消失，引出第 5 堂本地資料庫。

### 思考分享參考答案（結尾 10 分鐘）
1. **使用者把手機時間調快，訊息順序會亂嗎？**
   - 會，如果用本地 `ts` 排序就會亂。正式做法是一律信任 Server 單調遞增的 `seq`（尚未收到 ACK 的暫存訊息先放最後，收到 ACK 後依 `seq` 歸位）。
2. **訊息一萬則，收到 ACK 用 `indexWhere` 怎麼優化？**
   - 改用 `Map<String, Message>` 以 `clientMsgId` 為 key 做 O(1) 查找（或直接對接下一堂的 DB 主鍵索引）。

### 第二階段修改位置與卡關引導（starter 未列 TODO）
- **5 秒 ACK 逾時與重試要改哪裡**：都在 `app/lib/data/chat_controller.dart`
  - 送出訊息（`send` / `_transmit`）：為該 `clientMsgId` 啟動 5 秒 `Timer`，逾時沒收到 ACK 就把狀態改成 `MessageStatus.failed`。
  - `_onEvent` 收到 `ack` 時：務必先取消並移除對應 `clientMsgId` 的 `Timer`，否則 5 秒後會誤判成失敗。
  - `retry(Message msg)`：將狀態改回 `sending` 後重送（先故意用新 UUID 示範重複，再改回沿用原本 `msg.clientMsgId`）。
- **卡住引導**：若學員沒看到紅點，檢查 `ChatPage` 傳給 `MessageBubble` 時有沒有把 `status`（僅限自己的訊息）與 `onRetry: () => _chat.retry(m)` 接上。

### 第二階段修改位置與卡關引導（starter 未列 TODO）

  - `app/lib/ui/chat_page.dart`（未讀錨點）：改用 `CustomScrollView` 搭配 `center` key（`anchor: 0.75`）定位到第一則未讀並插入 `UnreadDivider`，同時加上「跳到最新 ↓」按鈕。
- **卡住引導**：若進房還是直接停在最底部，檢查 `open()` 是否有在補洞「之前」先記下原本的 `myReadSeq`（否則滑動後水位線被更新就找不到原本的第一則未讀了）。

## 第 10 堂：設計研討會（系統設計面試模擬）

- **Git 分支**：不需開新分支，以 `main`（第 9 堂完成版架構）為討論基準。
- **控制台設定**：**本堂不需要開 Server**。

### 課堂流程（60～90 分鐘）
1. **分組認領題目（5 分鐘）**：每組從以下 4 題挑一題（20 分鐘白板/紙上設計）：
   - **題目 1：多裝置同步**（同一帳號手機與平板同時登入：水位線記在人還是裝置？自己送的訊息怎麼同步到另一台？Outbox 怎麼處理？）
   - **題目 2：「對方正在輸入中」**（要不要存 DB？多久送一次節流？網路斷了或對方關掉 App 怎麼讓提示消失？）
   - **題目 3：訊息編輯與刪除**（`seq` 不可跳號怎麼辦？軟刪除標記、怎麼透過 Delta Sync 通知當時離線的人？）
   - **題目 4：傳一支 10MB 影片**（為什麼不塞進 WebSocket？先 HTTP 上傳拿 URL + 預覽縮圖 + 進度條 + 斷點續傳）
2. **上台報告與追問（每組 5 分鐘 + 追問 5 分鐘）**：
   - 其他組與講師扮演面試官追問邊界條件（斷線、重複、排序、效能）。
3. **費曼法總複習（10 分鐘）**：
   - 回到最終完整架構圖，讓學員兩兩一組，用自己的話從頭到尾把這 9 堂建立起來的系統講給對方聽。

## 附錄：跨週存檔與緊急重置

| 狀況 | 處理方式 |
| :--- | :--- |
| **下週繼續上課** | 用原本指令重啟：`dart run server.dart --admin=講師名 --data=state.json`，`seq` 與房間會接續上次進度。 |
| **新一梯次從頭開始** | 停止 Server → 刪除 `state.json` → 重啟 Server → **務必請學員刪除 App 重裝**（或清除 App 資料），否則本地 `seq` 會大於 Server 導致補洞與已讀錯亂。 |
| **忘記帶 `--data` 重啟了** | Server 記憶體清空，`seq` 回到 1。處理方式同上，請學員清除 App 資料或重裝。 |
| **學員回報「連線被拒 409（同名已在線）」** | 通常是 Hot Restart 留下的舊連線，Server 每 5 秒會做一次協議層 ping 清理死線，請學員等 5 秒重試，或在左欄檢查是否有重複名字。 |
| **左欄累積太多離線測試帳號** | 點左欄上方的 **「清除離線」** 按鈕，即可一鍵清掉已離線的測試帳號與空私人房。 |
